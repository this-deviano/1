# AMM-003 — Determinism scope in the browser preview layer (RATIFIED, SB-005)

Supersedes `AMM-003-candidate.md` (kept for history; the proposal was measured, not
argued, and the numbers selected **Branch A**).

Raised by: TASK-021 harness (SB-004) · root-caused by the TASK-026 bisect (SB-005).
Ruled: maintainer pre-authorised Branch A mechanically in SB-005 §4; the measured
numbers are the selection. Status: **RATIFIED**.

## 1. What was measured (TASK-026 bisect, docs/evidence/sb005/)

### STEP 0 — is the offline path native or pure JS?

`renderWav → renderBuffer` constructs an `OfflineAudioContext` and, through the
shared voice set, executes native nodes: `OscillatorNode`, `BiquadFilterNode`,
`DynamicsCompressorNode`, `StereoPannerNode`, `GainNode`, `AudioBufferSourceNode`.
**Native.** So Branch A was possible and had to be tested, not assumed.

### STEP 1 — clock leakage in the offline path: none

Every `ctx.currentTime` read in `engine.ts` sits in the **live** path
(`play`, `record`, `tickTimer`, `scheduleClicks`, `scheduleRange`, `noteOn`).
`renderBuffer`, `fireVoice`, the voices, `materialEvents` and `wavBlob` read no
clock. Ruled out.

### STEP 2 — frozen clock (Date.now + performance.now overridden): still varies

`determinism-steps.json`: with both clocks frozen, a 64-voice render still produced
4 distinct hashes in 4 runs. **Not clock leakage.**

### STEP 4 — same page vs a fresh page per render: varies both ways

Same page: 4 distinct hashes. Fresh page per render: 4 distinct hashes. So it is
**not** in-process module state, caches, or a reused `Float32Array`.
**Branch B (app state) is ruled out.**

### STEP 3 / node-class ladder — no PRNG required

`determinism-bisect.json`, LADDER A: every minimal graph — constant source,
oscillator→gain, +biquad, +panner, buffer→hp→lp, and the full
osc→biquad→panner→compressor→master chain — was **bit-stable** across 5 renders
in one process. **No node class introduces variance.** **Branch C (PRNG state
leak) is ruled out**: LADDER B rungs B3/B4/B6 contain no noise sources and no
PRNG at all, and still vary.

### STEP 5 — the app-controlled leg is bit-identical

`determinism-steps.json`: 20,000 PRNG draws from `seedStream(seed, "luthier/noise")`
hashed identically across 4 runs, and the model→event list hashed identically
across 4 runs. The non-WebAudio side is deterministic **as observed**, not merely
by construction.

### The decisive measurement — variance scales with graph size

LADDER B, 5 renders each, one process, app-length render (423,529 samples ≈ 9.6 s):

| graph | distinct hashes | max&#124;Δ&#124; | dBFS |
| ----- | --------------- | ----------- | ---- |
| 1 osc + chain | 1 | 0 | −inf (bit-identical) |
| 16 osc + chain | 1 | 0 | −inf (bit-identical) |
| 64 osc + chain | 5 | 2.980e-8 | −150.5 |
| 256 osc + chain | 5 | 5.880e-5 | −84.6 |
| 256 noise + chain | 5 | 2.980e-7 | −130.5 |
| 1024 osc + chain | 5 | 5.775e-4 | −64.8 |

The divergence is **introduced by Chromium's WebAudio render scheduling, not by
our code, and it grows with the number of nodes**. The app's own reference render
(≈ the 16–64 voice range) measures 4.17–4.77e-7 = −127.6 to −126.4 dBFS.

The exact internal mechanism (processing/summation order for a large graph, or
per-thread FP/denormal state) was **not isolated** and is not claimed. What is
established is the branch: the variance is platform-side and size-dependent.

## 2. The ruling (E-28 in the preview layer)

1. **App-controlled paths are byte-identical** — the model→event mapping and every
   PRNG stream. This is now backed by measurement (STEP 5), not construction.
2. **Through native WebAudio nodes**, determinism means
   `max|Δ| ≤ the per-browser measured cap`. Default cap: **−120 dBFS**.
3. The self-test **always** reports the measured `max|Δ|`, its dBFS, the cap, the
   bit-identity result, and **both hashes**. A pass that came from the cap prints
   as `amended-green`; the ledger records both behaviours.
4. SHA-256 equality remains the **normative-stack** target (ADR-0001: our own
   renderer with no browser FP variance) and a diagnostic here — never a gate that
   is known-unattainable.

## 3. Measured caveat recorded with the ratification

−120 dBFS is **not a universal constant**. The size ladder shows a legitimate
large arrangement can exceed it (1024 voices → −64.8 dBFS). The cap is calibrated
to the app's current reference render (−126.4 dBFS); **M2 must re-derive it** if
arrangements grow, or replace the absolute cap with a criterion that scales with
graph size. Recorded here so the next session inherits the number *and* its limit
rather than a comfortable fiction.

## 4. What was NOT done

- The gate was not widened silently: the old criterion was bit-exactness, and the
  change to a cap is exactly the text pre-authorised for Branch A.
- No platform verdict was claimed on inference. SB-004's "platform float noise"
  hypothesis happened to be right, but it was right by luck — the bisect found
  that a *specific node class* was **not** responsible, which the earlier
  reasoning had assumed.

## 5. Two thresholds, not one — and the convergence path (added SB-006)

Clarification of a conflation that appears in session handoffs. These are **two
different numbers with two different jobs**, and neither may be used for the other:

| Threshold | Value | Job |
| --------- | ----- | --- |
| **Determinism cap** (§2.2) | **−120 dBFS** | the E-28 self-test gate on a render through native WebAudio nodes |
| **Parity floor** (§2.4, R-2-AMENDED) | **−96 dBFS** | the constitution floor between the live and offline schedulers |

SB-005 evidence at the tip: determinism 5.36e-7 ≈ **−125.4 dBFS** (cap met,
`amended-green`); parity 4.77e-7 ≈ **−126.4 dBFS** (floor met, ~30 dB margin).
The cap stays **−120 dBFS**: lowering it to −96 to match the floor would be
widening a ratified gate to fit the other number, which §4 forbids.

**The convergence path back to bit-exactness is the M2 Unit architecture.**
The STEP-5 measurement is the load-bearing fact: the app-controlled leg — the
model→event mapping and every PRNG stream — is **bit-stable across runs**, while
the variance lives entirely in the native WebAudio projection. A Unit defined as a
**model-level pure function** with a **WebAudio projection** (M2-001…M2-007) moves
more of the render into the measured-bit-stable layer and shrinks the surface that
the cap has to cover. M2-009 re-derives the cap; it is not inherited blind.
